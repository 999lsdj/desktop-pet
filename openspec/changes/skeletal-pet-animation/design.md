# Design

## Context

动机见 `proposal.md` 的 Why。以下是塑造本方案的现状与约束。

代码现状（均在 `src/pet/`）：

- 绘制契约是"设备像素空间"。`run.ps1` 带 `-Dsun.java2d.uiScale=1`，`SPRITE_SCALE = 2`，
  精灵图按整数倍最近邻放大，所以绘制坐标等于物理像素、像素不发虚。骨架求值必须沿用这个契约。
- 角色由 `BodyRig` 从单张 105×123 精灵图剪出 4 片：躯干、提灯（杖＋手）、左右小腿。
  `erase()` 把杖区与腿区从躯干上挖空，因此关节一旦多转就会露出透明洞——现在靠摆幅小来回避。
- `PetWindow` 每帧合成：整体 `translate` ＋ `rotate(tilt)`，再按腿的髋枢轴、提灯的握点各自旋转贴图。
  没有任何网格或仿射变形，全部是刚体。
- `Pendulum` 已经是带重力回复、外部加速度耦合、阻尼与限位反弹的单摆，目前只挂在提灯上。
- 窗口形状不是每帧剪影：`envelopeShape` 预先覆盖整体倾斜 ±16 度与提灯摆动的极限，
  `applyShape()` 只在状态变化时 `setShape`。窗口尺寸由 `headroom / leftRoom / rightRoom`
  与 `groundX / groundY` 决定。
- 鼠标拖拽现在是"整窗平移"：只记 `pressScreen / pressWindow` 与一个 `dragging` 布尔，
  姿态不变；`bodyAt()` 是一个固定矩形包围盒，不按当前外形判断。
- 纵向位置恒等于 `groundLine - groundY`，拖动结束后角色会自动回到屏幕底部基准线。

素材与工具现状：

- 用户于 2026-10-15 确认保留当前 Q 版外观。正式素材来源是
  `assets/像素角色/master-transparent-800.png`（800×800，RGBA）。
- `assets/素材原图/character-reference-2048.png` 是黑底正常身材参考立绘；此前用于抠底实验，
  不再作为正式桌宠母图。下文旧实验数据保留作为历史验证，不代表当前素材已验收。
- `tools/prepare-sprite.ps1` 已支持浅色、深色与保留 alpha；Q 版使用 `-BgMode alpha`。
- 现有 105×123 精灵图里有 7595 种颜色，说明它是缩小后的插画、不是限色板像素画，
  因此 AI 路线不必凑色板，但边界与高光的还原仍然要验收。

外部环境：

- ComfyUI 0.39.0 便携版在 `E:\AI\ComfyUI_windows_portable`，自带 Python 3.13 与 PyTorch，CUDA 可用；
  使用 SDXL 1.0 Inpainting 0.1 单文件模型，先完成下载完整性和出图验证。
  本机有 SDXL 模板和 `InpaintModelConditioning` 等内置节点，无需安装自定义节点。
- 硬件：RTX 4060 Laptop，8188 MiB 显存；C 盘剩余约 18 GB，因此模型与产出放 D 或 E 盘。

## Goals / Non-Goals

**Goals:**

- 关节可连续弯折的骨架驱动动画，逐帧求值，与显示刷新同步。
- 发丝、袖子、袍摆、提灯用链式阻尼动力学驱动，带惯性滞后并收敛。
- 动作可无缝循环：拎起悬挂、招手、以及既有的踱步等动作。
- 素材产线可重复执行，像素补全只作用于缺失区域。

**Non-Goals:**

- 不做 AI 逐帧视频生成。ComfyUI 在本方案里只产出静态素材，不产出动画。
- 不引入任何 Java 第三方依赖（不引 Spine、libGDX 等），`build.ps1` 继续只用 `javac`。
- 不做 3D、不做 Live2D、不做口型或说话动作、不做坐下动作。
- 不做多显示器适配，也不处理角色素材的版权与仓库推送策略。
- 拆件粒度只按本次动作范围（拎起、招手、既有动作迁移）确定。
  后续若新增说话、坐下一类动作，需要重新评估骨树与拆件粒度。

## Decisions

### 1. 骨骼与蒙皮放在 Java 运行时自己算

自己写一个很小的 2D 骨架求值器：骨树、双骨 IK、按顶点权重做三角网格变形。

- 为什么：项目契约是零第三方依赖，`build.ps1` 只用 `javac`；只有实时求值才能同时满足
  "循环首尾无缝"与"对鼠标即时反应"两个验收点；烘焙序列帧会让素材量与状态组合爆炸。
- 备选：Spine 或 DragonBones 运行时（一个收费、一个已停维护，且破坏零依赖）；
  Blender 绑骨烘焙成序列帧（要新增工具链与一道烘焙工序，还丢掉实时交互）。

### 2. 形变分级：四肢关节蒙皮，发丝/袖/袍摆沿链变形，提灯保持刚体

```
   root（站立时锚在脚下；拎起时锚在鼠标抓点）
    +- spine 躯干（1-2 节，可轻微弯）
    |   +- head 头
    |   |   +- hair 发丝链 A-B-C        <- Verlet 节点驱动，材质沿链蒙皮
    |   |   +- 角 / 发饰                <- 刚体贴图
    |   +- 远侧臂 upperArm -> forearm -> hand   <- 关节蒙皮
    |   +- 近侧臂 upperArm -> forearm -> hand   <- 关节蒙皮
    |   |        +- 提灯 staff（复用现有 Pendulum，挂点 19,66）
    |   +- 袍摆链 coat L / coat R        <- Verlet 节点驱动，材质沿链蒙皮
    +- 近侧腿 thigh -> shin -> foot       <- 关节蒙皮
    +- 远侧腿 thigh_far -> shin_far -> foot_far
```

- 为什么：链式骨骼是实现"关节灵活"最便宜的部分，而这个角色最抢眼的动感恰好全在链上
  （长发、宽袖、长袍飘带、提灯）；真正非蒙皮不可的只有肩、肘、髋、膝四处。
- 备选：全部蒙皮（工作量大、收益低）；全部保持刚体（就是现状，做不到关节灵活）。

2026-10-15 分层预览补充：链负责求角度，长发、宽袖和衣摆的图形通过限定链骨集合的权重连续变形，
避免把长条材质再切成互不相连的刚体。当前离屏驱动先用周期函数验证贴图，尚未连接 Verlet 动态结果。

### 3. 链式柔性用 Verlet 积分 ＋ 距离约束，单摆只留给提灯

第一版按"把 `Pendulum` 串成链、每节由父节点末端的加速度驱动"实现，**自检直接证伪了它**：
所有链节等长 → 固有频率相同 → 每一级都正好踩在上一级的共振点上，
品质因数约 7 逐级相乘（7、49、343…），越往下振幅越大，最后死卡在限位。

实测（4 节、每节 12 像素、阻尼 1.2、增益 1.0，挂点在 0.2 秒内平移 30 像素后松手）：

| 链节 | 松手后 1 秒峰值 | 6 秒后末 1 秒峰值 |
| --- | --- | --- |
| link0 | 40.0 度 | 2.4 度（正常衰减） |
| link1 | 40.0 度 | 30.8 度 |
| link2 | 40.0 度 | 40.000 度（精确停在限位） |
| link3 | 40.0 度 | 40.000 度（精确停在限位） |

把限位从 40 度收到 8 度，后两节依然精确停在 8 度——所以这不是"限位太宽"，是构造本身不稳定。

改成 Verlet 积分 ＋ 距离约束：每帧节点按惯性前进并受重力，然后把根节点钉回挂点，
迭代把相邻节点距离拉回杆长，最后按每节的限位角夹一次方向（防止发丝翻到头顶上去）。

- 为什么：稳定性由构造保证，没有固有频率，也就没有共振级联；参数只剩杆长、阻尼、限位角，
  比等长单摆链更少也更好理解。这也是游戏里头发／布料的标准做法。
- `Pendulum` 保留给提灯——它单个用着正常（长度 90 像素，由平滑移动的握点驱动）。
- 备选：继续在单摆链上打补丁（给链节做长度锥度、逐级加大阻尼、逐级降低驱动增益）。
  那是"在调参上面再调参"，而且共振能否压住没有保证，已被实测否掉。

### 4. rest pose 采用用户确认的 Q 版持杖站姿

- 为什么：骨骼可以以任意姿势作为 rest pose；桌宠本身就是站立踱步，Q 版持杖姿势合乎角色设定；
  这样省掉姿势迁移模型和随之而来的整图风格一致性问题。
- 备选：先用图像编辑模型把立绘转成正面 A-pose（动作自由度更大，但每次都要重做风格一致性，
  工作量和风险都上一个台阶）。
- 代价：正面朝向、坐下这类动作以后要重来一次，已在 Non-Goals 里记下。

### 5. 招手用"杖杵地 ＋ 握杖手招手"

- 为什么：沿用用户已经确认的握杖手招手方案；"杖离开手、立在地上"
  的逻辑现有代码已有（`PLACED_LEAN`、`PLACED_DX` 与"放下挂灯"那段），可直接复用。
  Q 版握杖手在腰侧，需要从当前持杖姿态抬臂；不能沿用 2048 参考图里手在脸旁的假设。
- 备选：造远侧整条手臂（贵，且手臂在身体另一侧会被躯干挡）。

### 6. Q 版母图从 800 原图按整数倍降采样

- 正式输入固定为 800×800 的 Q 版透明原图；保持持杖姿势、角色比例与像素风。
- 母图记录满画布尺寸、内容裁剪框、原点偏移和整数倍率。先按现有素材链的 5 倍降采样
  验证（满画布 160×160），对照当前 105×123 精灵的屏上观感；若关节细节不足，
  再比较 4 倍降采样（满画布 200×200）。不得把 2048 参考图的裁剪坐标沿用到 Q 版。
- 补洞在 800 原图或不大于 1024 的局部图上做，合成后再按同一整数倍率降采样。
- 旧任务 6.2 的完成记录只适用于 2048 参考图，因此改用 Q 版后重新验收。

### 7. 窗口形状继续用包络，不改成每帧剪影

- 为什么：`envelopeShape` 的模式已经存在且不在每帧重算，性能上有保证；肢体摆幅有界，
  包络可以覆盖极限摆位。
- 做法：按骨架极限摆位重算包络（每根链取最大摆角，四肢取动作极限），窗口留边按新包络取。
  必要时按状态分级（待机用小包络、招手用大包络）。
- 备选：每帧重算剪影（`Area` 构造成本高，逐帧做会掉帧）；改成整窗矩形（角色以外会挡鼠标，
  破坏现有体验）。

### 8. 鼠标命中改用骨头包围盒的并集

- 为什么：现有 `bodyAt()` 是固定矩形，骨架把肢体摆出去之后会框不住，也会框住空白；
  按骨头包围盒求并集便宜且足以满足"点得到伸出去的手"这一验收点。
- 备选：每帧生成剪影区域做命中（贵）；保持固定矩形（不满足规格要求）。

### 9. 悬挂实现为"换锚点"，不额外造素材

站立时锚在脚下，拎起时锚在鼠标抓点，重力方向不变，链式部件自然下垂并滞后摆动。

- 需要补的一处：现在只记了鼠标的屏幕坐标，要额外记下按下处在角色内的局部坐标，悬挂支点才正确。
- 为什么优于新做一套悬挂素材：下垂是链式动力学天然给出的结果，零新增素材。

### 10. ComfyUI 只出静态素材，统一使用 SDXL 本地补洞工作流

- 模型固定为 `sd_xl_base_1.0_inpainting_0.1.safetensors`；从内置 SDXL 模板的加载、
  文本编码、采样、解码节点扩展，使用 `InpaintModelConditioning` 传入图像和缺口蒙版。
- FLUX/Qwen 模板与该 checkpoint 不兼容，不作为当前执行路径，也不因此追加下载其他模型。
- 先用 Q 版衣袖的小区域验证整个流程，再逐项处理关节、躯干、手掌、小臂和独立袖子。
  一次补洞成功不等于所有素材通过验收，逐项在最终尺寸下检查风格、接缝与关节余量。
- 输出以蒙版合回原 RGBA 图，蒙版外直接保留原像素；保存原图、蒙版、原始生成图、
  合成结果与像素差异报告，避免 VAE 解码改动已有区域。
- 补洞分辨率控制在 1024 以内，在本机 8 GB 显存上实测；不需要视频模型或自定义节点。
- 备选：模板库里的云 API 工作流（需要 API key 与额度，走的不是本机显卡）；
  视频模型逐帧（与骨骼路线冲突，且丢掉循环与实时交互）。

### 11. 素材产线以命令驱动

- 为什么：规格要求产出可重复执行、缺失项可逐条核对；ComfyUI 提供 HTTP 接口，
  可以脚本化提交与取回，产出可留痕验收。
- 备选：手工在 ComfyUI 界面点击（不可重复，验收没有凭据）。

### 12. 先做最小验证，再动美术

- 为什么：素材替换是破坏性的（旧精灵图与 `BodyRig` 坐标常量作废），而 Java 侧自写的蒙皮
  是本方案里唯一没有现成代码可抄的部分。先用现有 105×123 图配一个粗糙测试网格把耗时测出来，
  再决定是否全量返工。

### 13. 蒙皮权重按部件约束，不按全图距离

第二轮验证证明：用单一的距离衰减给整张图分配权重，会把**同一块材质绑到不同的骨头上**，
姿势一大就撕裂（提灯杖是典型受害者，它同时靠近手臂和腿）。所以权重必须"先认部件、再认距离"：

```
   每个部件先声明自己属于哪条骨链（部件 -> 允许参与的骨头集合）
       提灯杖  -> 只许 staff 一根（整根刚性跟随）
       小腿    -> 只许 shinNear / thighNear
       躯干    -> 只许 root / torso
       发丝    -> 只许发丝链自己的几节
   然后在"允许集合"内部再按距离衰减分配权重
```

- 为什么：这是"材质不会自我撕裂"的唯一可靠办法，也是所有正经的 2D 剪纸／骨骼动画的做法。
- 代价：**必须先有分层部件才能做**——扁平的一张图里无从声明"这块属于哪条链"。
  也就是说任务 2.3 的后半段（接进 `PetWindow`）实际要排在任务 7.1（拆件）之后。
- 备选：保持全图距离权重，把动作幅度限制在小范围内（等于放弃"关节灵活"这个目标，不可取）。

## Measured Results

Q 版轮廓分层与补洞候选（2026-10-15）：

- 分层定义为 `assets/rig/q-chibi.layout.json`，当前 22 层，手／杖／提灯分离。
  可见像素独占归属，零碎轮廓像素归入最近区域，避免在躯干层残留悬浮碎片；
  这份轮廓仍是待精修候选，不能据此断言每块材质的语义归属都正确。
- 隐藏余量只允许出现在前景完全遮住的位置。首轮补图覆盖了原姿态的 73 个像素，
  修正规则后重组 RGBA 差异恢复为 0。当前 10 个补洞任务合计 944 个层像素，
  蒙版映射到 800 原图执行，结果只写入各层缺失区域。
- 关节检查扫描 13 处、163 个角度样本，统计连接区域内部缺口；
  对原透明边缘做一像素内缩，避免把轮廓自然移动误报成内部洞。
  该计数不能证明外轮廓连续，也不替代后续组合动作与连续蒙皮的验收。
- 所有候选、摘要和角度检查保存在 `assets/rig/q-chibi-draft/`；
  原始输入、蒙版、请求、工作流及逐项报告保留在 `_tmp/q-parts/`。
  `runtime_ready` 保持 false；7.1–7.3 仍在进行中。

Q 版素材复验（2026-10-15，用户确认保留外观后）：

- `master-transparent-800.png` 使用 `-BgMode alpha -BlockSize 5`，保留原透明度，不再按颜色抠底。
- 满画布 800 / 5 = 160，内容框 `[139,81,668,699)`，裁剪后 105×123；
  `manifest.json` 同时记录边界、实际采样范围、偏移、倍率和源文件 SHA-256。
- 与当前 `assets/sprites/pet-base.png` 逐像素对比：差异 **0**；原图 alpha 变化 **0**；四角透明。
- 证据：`_tmp/q-master/manifest.json`、`_tmp/q-master/comparison.png`。重新完成任务 6.2。
- 以下 2048 图的旧实验只保留为背景处理验证，不作为 Q 版正式素材来源。

第一版验证（2026-10-15，本机实测）。用现有 105×123 精灵图按 2 倍最近邻放大到 210×246
（与屏上尺寸一致），以髋线为折痕做 ±30 度正弦弯曲，逐帧计时 240 帧、丢弃前 60 帧预热，
渲染进 340×380 缓冲图；求值与绘制分开计时。

| 方案 | 求值（顶点位移） | 绘制（逐三角形贴图） | 合计 |
| --- | --- | --- | --- |
| 网格 12×14（336 个三角形） | 平均 0.008 ms | 平均 0.997 ms，P95 1.286 ms | 约 1.0 ms |
| 网格 24×28（1344 个三角形） | 平均 0.009 ms | 平均 2.233 ms，P95 2.534 ms | 约 2.2 ms |
| 对照：整图直贴（现在的做法） | 无 | 平均 0.077 ms | 0.08 ms |

120 Hz 的每帧预算是 8.33 ms。两种网格密度都留在预算内（约占 12% 与 27%），
求值几乎不花时间，代价全在逐三角形贴图。**结论：继续走蒙皮方案**，
不启用"纯链式骨 ＋ 四肢分段刚体"那条备选。密度上 24×28 仍有余量，
正式蒙皮可按"关节附近加密、其余稀疏"来分配三角形，把预算花在看得见的地方。

验收图在 `_tmp/shots/mesh-check.png`：第一行是弯曲结果，第二行叠加网格线。
0/15/30/45 度四档下关节处都是连续弧线，没有透明缺口、没有硬折角，

第二轮验证（同日，线性混合蒙皮）：

第三轮验证（同日，链式柔性改用 Verlet 积分 ＋ 距离约束）：

| 检查项 | 结果 |
| --- | --- |
| 松手后 1 秒关节峰值 | 76.20 度（第 1 节相对竖直，不受关节限位约束） |
| 12 秒后末 1 秒峰值 | 0.043 度 |
| 杆长最大偏差 | 0.000000 像素（约束求解精确保持杆长） |
| 数值 | 全程无 NaN／Inf |

同一份暴力输入（挂点 0.2 秒平移 30 像素）在等长单摆链上死卡限位、永不收敛；

第五轮验证（同日，链参数搬进 `config.properties`）。自检改成逐条链报数，

## Risks / Trade-offs

2026-10-15 膝盖修正：旧距离权重在 11 像素的小腿上覆盖到脚踝，脚踝转 20° 会令膝中心漂移 0.177852 像素；
旧线性混合在膝弯 34° 时把 8 像素截面压到 7.651734。腿部现选择 `joint-chain`，
只在相邻关节最多前后 4 像素的范围内平滑混合，并绕共同枢轴插值旋转角。其他材质保留原距离权重。
预览髋摆幅 ±17°→±7°，膝峰值 34°→24°，抬腿半周弯曲、落下回直且两侧镜像。
截面、踝膝隔离、跨层坐标一致性及 721 相位检查通过；自然步态仍待正式动作接入验收。

2026-10-15 后续用户反馈（待实现）：上述预览仍未通过视觉验收。腿部摆幅目标更新为约 12°，
沿现有髋角参数口径暂按相对站姿 ±12°调试；不把此值应用到所有膝踝关节。
画面左腿几乎不动、双腿像跳动，需要检查交替相位、支撑／摆动阶段和遮挡后的可见运动。
画面右腿抬起时仍内凹，脚踝枢轴、脚掌朝向及小腿到脚部的轮廓／遮挡是优先排查方向，尚无确定根因。
先将画面左右与 near/far 骨名对应，再用同相位图及连续动画验收；原数值回归不能替代这一视觉要求。
用户要求当天只记录，下一次工作从此处继续；目前代码仍为 ±7°诊断预览，未实施新目标。

- [Java 侧实时蒙皮性能不达标] → 先做最小验证测单帧耗时；若不达标，退到
  "纯链式骨骼 ＋ 四肢分段刚体"（每段独立贴图、靠重叠余量藏缝），仍有明显关节弯折但不需要蒙皮。
- [宽袖补不出来，招手穿帮] → 把"独立袖子层"单列为验收项；补得不好就退回
  "招手幅度小、袖子少动"的版本，并在规格的招手场景里保持可验收。
- [关节重叠余量不足，转出透明缺口] → 拆件时统一在关节两侧留重叠余量，
  验收时逐关节取动作极限角度检查（对应规格里的关节余量场景）。
- [黑底立绘抠底失败] → 现有泛洪判据只认近白背景，必须扩展并补一条"深色背景"验收；
  抠底失败会直接毁掉后续全部素材。
- [素材替换不可逆] → 旧精灵图与拆件逻辑在验证通过前保留，母图与拆件产出放独立目录，可整目录回退。
- [包络变大导致挡鼠标] → 在"不裁掉肢体"与"少挡空白"之间取平衡，必要时按状态分级包络。
- [显存与磁盘] → 补洞分辨率控制在 1024 以内；模型与产出放 D 或 E 盘，不动紧张的 C 盘。
- [风格漂移] → 补全结果必须以最终母图尺寸拼回原图验收，而不是在 2048 分辨率下目测。
- [全图距离权重把材质撕开] → 权重按部件约束（见 Decisions 第 13 条），
  并且任务 2.3 的后半段要等分层部件做出来之后再做；在那之前只保留自检与验收图，不接进桌宠。

## Migration Plan

1. 最小验证：不换素材，用现有 105×123 图配粗糙测试网格，测 Java 侧每帧蒙皮耗时。
2. 素材返工：800 Q 版透明原图 → 验证透明边缘与整数降采样 → 按 Q 版重新量坐标并拆件（含关节重叠余量）。
3. ComfyUI 补全缺失区域：关节缝、被发丝与袖子压住的躯干、张开的手掌、抬起的小臂、独立袖子层；
   逐项与原图拼回验收。
4. 骨架接入：骨树、链式柔性（Verlet 积分 ＋ 距离约束）、蒙皮，并把既有踱步等动作改为骨架驱动。
5. 拎起：状态机加拎起状态、记录局部抓点、换悬挂锚点、落地缓冲。
6. 招手：接入补全出来的手臂与袖子素材。
7. 收尾：窗口包络与留边、命中判定、配置项与日志。

回滚策略：素材与骨架定义放在独立目录，旧 `assets/sprites/pet-base.png` 与旧拆件逻辑
在验证通过前不删除，任何一步不达标都可以整目录退回。
