# 骨骼与拆件说明

这份文档记录角色的骨架定义、坐标约定，以及骨架与拆件的对应关系。
前半部分是当前 `BodyRig` 运行版；文末记录新的 `LayeredRig` 分层离屏预览，二者尚未合并。
改动其中任何一项坐标后，按最后一节的步骤跑一遍自检。

## 坐标约定

- **原生像素坐标系**：原点在精灵图左上角，x 向右、y 向下。现在精灵图是 105×123。
- **窗口绘制**：`PetWindow` 把原生坐标乘以 `SPRITE_SCALE`（当前 2）后画到屏幕上，
  所以屏幕上是 210×246 的整数倍放大。骨架也活在原生坐标里，由调用方按倍率放大。
- **角度**：0 度指向 +X（右），90 度指向 +Y（下），-90 度指向（上）；顺时针为正，
  与 `AffineTransform.rotate` 一致。
- **世界方向 vs 相对角度**：建骨时给的是**世界方向**（读数直观），
  `Skeleton.add` 内部换算成相对父骨的角度存起来。

## 骨树

```
root（脚底中心，朝上到髋线）
├─ torso（髋线 → 画布顶）
│   ├─ head（画布顶再往上 24 像素，只作参照）
│   └─ upperArm → foreArm（末端精确落在握点上）
│                      └─ staff（挂在握点上，指向杖底）
├─ thighNear → shinNear（近侧腿，髋 → 膝 → 脚）
└─ thighFar  → shinFar（远侧腿）
```

## 与拆件的对应关系

骨架没有自己写死一套坐标，四个已知关节**直接读 `BodyRig` 的值**，
所以"骨架和拆件对齐"是结构上的，不靠维护两处常量：

| 拆件里的值 | 骨架里的位置 |
| --- | --- |
| `rig.hip(0)` = (44, 89) | `thighNear` 起点 |
| `rig.hip(1)` = (61, 89) | `thighFar` 起点 |
| `rig.grip()` = (19, 66) | `foreArm` 末端 ＝ `staff` 起点 |
| `rig.staffFoot()` = (17, 121) | `staff` 末端 |
| `rig.width()` / `rig.height()` | 画布 105×123，`root` 取 (宽/2, 高) |

**肩与肘是估算值**：现有立绘是扁平的一张图，肩关节和肘关节的位置看不出来，
先按 (48, 46) 与 (36, 60) 放。等第七组重新拆件、做出分层部件之后，
从新部件上量出真实位置再改 `Skeleton.from`。

## 部件命名约定

- 现有拆件只有四件：`body`（躯干）、`staff`（杖＋手）、`leg(0)` 近侧小腿、`leg(1)` 远侧小腿。
- 重新拆件后的分层部件沿用骨架的骨头名：`head`、`torso`、`upperArm`、`foreArm`、
  `thighNear`、`shinNear` 等，一个部件对应一根骨头，避免再另外起一套名字。
- 关节两侧的部件要留重叠余量（见 OpenSpec 变更里的 `sprite-asset-pipeline` 规格）。

## 怎么加一根新骨头

### Q 版分层候选的坐标记录

`assets/rig/q-chibi.layout.json` 是本轮候选坐标来源，仍为 105×123。
原图坐标换算为 `(139 + 5x, 81 + 5y)`，采样框 `[139,81,664,696)`。
候选输出共 22 层，手、杖和提灯独立；小臂在原图中不可见，初始空层由补洞候选填充。
以下是新量的候选关节，尚未替换上文 `BodyRig` 和 `Skeleton` 的运行时常量：

| 关节 | 近侧候选 | 远侧候选 |
| --- | --- | --- |
| 肩 | (39,51) | (63,51) |
| 肘 | (33,62) | (70,63) |
| 腕 | (25,69) | (78,77) |
| 髋 | (44,81) | (56,81) |
| 膝 | (46,97) | (59,97) |
| 踝 | (46,108) | (62,108) |

候选目录中的关节图只验证单关节刚性摆位。新的 `LayeredRig` 已从这些坐标创建骨头，
并提供连续蒙皮离屏预览；`PetWindow` 仍使用旧运行路径。

### 添加骨头示例

```java
// 起点写在精灵坐标系里，内部会自动换算成父骨局部系
s.add("coatTail", "torso", 0, 0, 180, 30);
```

加完跑一次自检（下一节）。头发、袖子、袍摆这些将来挂成链的部分，
每节都是一根这样的骨头，再由链式动力学给出 `deltaDeg`。

## 分层离屏骨架与运行版的边界

`tools/export-q-rig.py` 从 layout 的关节位置创建新骨树，而不是读取旧 `BodyRig`。
根节点位于两髋中点；躯干连到颈点，双腿各有大腿、小腿、脚，双臂各有上臂、小臂、手。
杖挂在近侧手，提灯挂在杖；双侧发丝挂在头，衣摆挂在躯干，袖子挂在对应小臂。
柔性路径默认值在导出器中；可用 layout 的 `rig_paths` 显式覆盖每条链的父骨和节点。

每层 properties 记录图像文件与 SHA-256、材质组及允许影响它的骨头名。
`Skin` 仅在允许集合内分配距离权重；同一条腿或手臂的各层共用全局 4 像素网格与骨集合，
使重叠像素使用同样位移。长发、袖子和衣摆沿对应链节点蒙皮，杖与提灯保持刚体。
`LayeredRig` 校验贴图尺寸、哈希、骨顺序、路径边界与有限坐标后逐层绘制。

```powershell
$py = 'E:\AI\ComfyUI_windows_portable\python_embeded\python.exe'
& $py -X utf8 tools\export-q-rig.py --output _tmp\layered-preview\final\rig
pwsh -File build.ps1
java '-Djava.awt.headless=true' -cp out pet.LayeredRigSelfTest
java '-Djava.awt.headless=true' -cp out pet.LayeredRigPreview _tmp\layered-preview\final\rig _tmp\layered-preview\final
```

以上命令不启动桌宠。`LayeredRigPreview` 的周期角度仅检查真实素材的变形与合成；
`ChainRig` 的 Verlet 数值自检仍是另一条证据链，二者尚未连接进 `PetWindow`。
OpenSpec 3.2 原先只凭骨架线验证勾选，现已纠正为未完成。
离屏画面仍有髋部拉伸和隐藏材质问题，不能把它当作正式踱步或待机效果。

## 旧骨架数值自检

```powershell
pwsh -File build.ps1
java -Dsun.java2d.uiScale=1 -cp out pet.RigPreview
```

看两处：

1. `logs/pet.log` 里应该出现
   `骨架自检 关节与拆件坐标最大偏差 0.000000 原生像素，骨头 N 根`。
   偏差不为零说明新坐标和拆件对不上，`gap()` 会额外写一行 `ERROR` 指出是哪个关节。
2. `_tmp/shots/skeleton-check.png`：三格分别是静止姿态、摆过腿和杖的姿态、
   用 IK 够目标点的姿态。骨线应该是蓝线、关节是橙点、根节点是紫点，
   角色被画成半透明方便对照；骨线和角色对不上就说明倍率或坐标写错了。

`RigPreview` 还会顺带打出 `IK 自检`（随机目标的末端误差、超范围时的夹取结果），
以及网格变形的逐帧耗时。这些都是开机跑一次就能看到的，不需要额外环境。
