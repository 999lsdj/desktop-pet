# 素材产线说明

从一张角色立绘，到"能绑骨的分层部件"，要走三步。前两步是纯脚本、随时可复跑；
第三步要 ComfyUI 补像素，属于外部工具，单独说明。

```
   [立绘 PNG]
        |
        |  1. tools/prepare-sprite.ps1     抠底 + 整数倍降采样
        v
   透明底母图 (满画布 256x256) + 角色内容裁剪 (231x219)
        |
        |  2. tools/cut-parts.ps1          按矩形拆件，关节两侧留重叠余量
        v
   分层部件 + 拼装自检 + 每个关节的"缺口报告"
        |
        |  3. ComfyUI 补缺口                （见下文，模型在 E:\AI\...）
        v
   可绑骨的分层部件
```

## 1. 抠底与降采样

```powershell
pwsh -File tools\prepare-sprite.ps1 -In assets\素材原图\character-reference-2048.png -OutDir _tmp\bg-test -BlockSize 8
```

- `-BgMode auto`（默认）会先从四角取样判断背景深浅：这张立绘是黑底，实测四角亮度 0.0，
  自动走深色判据。要强制可传 `white` 或 `black`。
- `-BgDarkThreshold 20`：深色背景下三个通道都不超过它才算背景。调大容易咬到角色轮廓。
- `-BlockSize 8`：2048 / 8 = 满画布 256×256，是 2048 的整数分之一，边缘不会发糊。

产出（`-OutDir` 下）：

| 文件 | 是什么 |
| --- | --- |
| `sprite-full-transparent.png` | 抠好底的**满画布**图（2048×2048，四角透明） |
| `sprite-native-<w>x<h>.png` | 按内容裁剪并降采样的母图（本次 231×219），绑骨用这张 |
| `preview-native-4x.png` | 4 倍最近邻预览，肉眼验收用 |

脚本会打印一行倍率记录，例如
`downsample: block 8, full canvas 256x256 (= 2048 的 1/8), content crop 231x219`。

## 2. 拆件与缺口报告

```powershell
pwsh -File tools\cut-parts.ps1                                  # 默认切 assets\sprites\pet-base.png
pwsh -File tools\cut-parts.ps1 -In <图> -OutDir <目录> -Overlap 3
```

`-Overlap` 是关节两侧的重叠余量：每个部件往外多留这么多像素，转起来才不容易露缝。

产出（`-OutDir` 下）：

| 文件 | 是什么 |
| --- | --- |
| `part-<名字>.png` | 各分层部件（含重叠余量；躯干层已挖掉别的部件占的格子） |
| `reassembled.png` | 把部件按原位置贴回去的结果，用来和原图比对 |
| `gap-<部件>-<角度>.png` | 该部件转到极限角度后，缺的像素标成红色 |

两件要看的数：

1. **拼装自检**：`reassembly: 全不透明像素不匹配 0 / N`。
   这个数必须是 0；不为 0 说明拆件坐标错了或者丢了像素。
   同时会报"含边缘过渡共 M 个"，那是 3 像素重叠余量里接近不透明的边缘被叠了两次、差 ±1，
   属于重叠的必然代价，不是错误。
2. **缺口报告**：`gap report` 里每个关节的像素数。
   这些是立绘上被别的部件盖住、从来没画过的地方，**就是第 3 步要交给 ComfyUI 补的清单**。

当前实测（旧 105×123 精灵图、BodyRig 那套坐标）：近侧腿 66、远侧腿 99、提灯杖 1031 像素。

## 3. 用 ComfyUI 补缺口（尚未开始）

- 模型：SDXL 1.0 补洞 0.1 的单文件权重，放在
  `E:\AI\ComfyUI_windows_portable\ComfyUI\models\checkpoints\`。
- 精度按最终尺寸倒推：母图只有 256 宽，补洞在 1024 以内做完，降采样后看不出差别，
  8 GB 显存够用，不需要视频模型。
- 验收：补全图拼回母图尺寸之后，缺失区域之外的像素必须与原立绘一致，
  且拼接处没有可见接缝与色差。

## 已知的坑

- **墨迹笔触会把内容包围盒撑大**。这张立绘带着大量接近黑色的墨迹装饰，在黑底上几乎看不见，
  抠底之后变成可见黑块，包围盒被撑到 1848×1757，而角色本体只有七百多像素宽。
  所以拆件的裁剪范围要按**角色本体**量，不能直接用脚本报的内容包围盒。
- **重叠余量会让边缘像素被叠两次**，所以拼装自检要分开统计"全不透明"和"含边缘过渡"。
- **部件是按矩形裁的**，不是按轮廓。重叠余量给足才不会露缝；余量最终还是不够的地方，
  就落到缺口报告里交给 ComfyUI。
