# 素材产线说明

从一张角色立绘，到"能绑骨的分层部件"，要走三步。前两步是纯脚本、随时可复跑；
第三步通过本机 ComfyUI 补像素。正式素材为用户确认的 Q 版角色，
输入是 `assets/像素角色/master-transparent-800.png`；2048 黑底参考图只作抠底回归验证。

```
   [立绘 PNG]
        |
        |  1. tools/prepare-sprite.ps1     抠底 + 整数倍降采样
        v
   透明底母图 (满画布 160x160) + 角色内容裁剪 (105x123)
        |
        |  2. tools/cut-parts.ps1          按矩形拆件，关节两侧留重叠余量
        v
   分层部件 + 拼装自检 + 每个关节的"缺口报告"
        |
        |  3. ComfyUI 补缺口                （见下文，模型在 E:\AI\...）
        v
   可绑骨的分层部件
```

## 1. 抠底与降采样

```powershell
pwsh -File tools\prepare-sprite.ps1 -In assets\像素角色\master-transparent-800.png -OutDir _tmp\q-master -BgMode alpha -BlockSize 5
```

- `-BgMode alpha` 保留已透明的 Q 版原图，不会把相连的黑色描边和衣物当背景删掉。
- `-BgMode auto`（默认）用于纯色背景图，先从四角判断深浅；可强制 `white` 或 `black`。
- `-BgDarkThreshold 20`：深色背景下三个通道都不超过它才算背景。调大容易咬到角色轮廓。
- `-BlockSize 5`：800 / 5 = 满画布 160×160。内容框从 (139,81) 开始，裁剪后 105×123。
  实测与当前桌宠精灵逐像素一致，保持屏幕大小和观感；倍率必须整除原图宽高。

产出（`-OutDir` 下）：

| 文件 | 是什么 |
| --- | --- |
| `sprite-full-transparent.png` | **原尺寸满画布**图（本次 800×800，保留 alpha） |
| `sprite-native-<w>x<h>.png` | 按内容裁剪并降采样的母图（本次 105×123），绑骨用这张 |
| `preview-native-4x.png` | 4 倍最近邻预览，肉眼验收用 |
| `manifest.json` | 来源、SHA-256、原尺寸、满画布降采样尺寸、内容框、实际采样框、偏移、倍率 |

脚本会打印一行倍率记录，例如
`downsample: block 5, full canvas 160x160 (= 800 的 1/5), content crop 105x123`。
为复现既有精灵，内容尺寸取整下舍；被舍去的尾部范围可从 manifest 的两个 bounds 字段核对。

## 2. 拆件与缺口报告

```powershell
pwsh -File tools\cut-parts.ps1                                  # 默认切 assets\sprites\pet-base.png
pwsh -File tools\cut-parts.ps1 -In <图> -OutDir <目录> -Overlap 3
```

`-Overlap` 是关节两侧的重叠余量：每个部件往外多留这么多像素，转起来才不容易露缝。

产出（`-OutDir` 下）：

| 文件 | 是什么 |
| --- | --- |
| `part-<名字>.png` | 各分层部件（含重叠余量；躯干层已挖掉别的部件占的格子） |
| `reassembled.png` | 把部件按原位置贴回去的结果，用来和原图比对 |
| `gap-<部件>-<角度>.png` | 该部件转到极限角度后，缺的像素标成红色 |

两件要看的数：

1. **拼装自检**：`reassembly: 全不透明像素不匹配 0 / N`。
   这个数必须是 0；不为 0 说明拆件坐标错了或者丢了像素。
   同时会报"含边缘过渡共 M 个"，那是 3 像素重叠余量里接近不透明的边缘被叠了两次、差 ±1，
   属于重叠的必然代价，不是错误。
2. **缺口报告**：`gap report` 里每个关节的像素数。
   这些是立绘上被别的部件盖住、从来没画过的地方，**就是第 3 步要交给 ComfyUI 补的清单**。

当前实测（旧 105×123 精灵图、BodyRig 那套坐标）：近侧腿 66、远侧腿 99、提灯杖 1031 像素。

## 3. 用 ComfyUI 补缺口

- 模型：SDXL 1.0 补洞 0.1 的单文件权重，放在
  `E:\AI\ComfyUI_windows_portable\ComfyUI\models\checkpoints\`。
- 工作流：`tools/workflows/sdxl-inpaint-api.json`，使用 ComfyUI 内置 SDXL 节点和
  `InpaintModelConditioning`；FLUX/Qwen 模板不能直接加载此模型。
- 补洞在 800 原图或不大于 1024 的局部图上完成，以最终尺寸验收；显存以本机实测为准。
- 验收：补全图拼回母图尺寸之后，缺失区域之外的像素必须与原立绘一致，
  且拼接处没有可见接缝与色差。

首次准备：

```powershell
$py = 'E:\AI\ComfyUI_windows_portable\python_embeded\python.exe'
& $py -X utf8 -s tools\download-comfy-model.py
# 下载器支持断点比对、4 路分段下载和中断重试；最后必须出现 SHA-256 校验通过。
# 在 ComfyUI_windows_portable 目录运行（仅监听本机）：
# .\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build --disable-auto-launch --listen 127.0.0.1 --reserve-vram 1
```

验证一小块衣袖（不替换运行中的桌宠素材）：

```powershell
& $py -X utf8 -s tools\comfy-inpaint.py --smoke --prepare-only
& $py -X utf8 -s tools\comfy-inpaint.py --smoke
& $py -X utf8 -s tools\test-comfy-pipeline.py
```

已有独立下载进程时，可运行 `tools/verify-comfy-after-download.ps1 -DownloadProcessId <下载PID>`，
它等待该进程退出后重新校验大小及 SHA-256，再连续执行两次同目录补洞验证。
状态在 `_tmp/comfy/setup-status.json`，两次报告在 `smoke-run-1.json`、`smoke-run-2.json`。
`waiting_download` 表示仍未开始出图；`failed` 表示停止且保留错误；
`checks_passed_visual_review_pending` 只表示自动检查通过，仍需查看 `smoke/comparison.png`。

正式区域使用 `--image <原图.png> --mask <蒙版.png> --out <独立目录> --prompt <区域描述>`。
蒙版为白色补洞、黑色保留；原图和蒙版同尺寸，宽高为 8 的倍数。可传 `--seed`、`--steps`、
`--downsample`；倍率必须整除宽高。每个部件独立目录，参数一致可重复运行。

产出包含 `input.png`、`model-input.png`、`mask.png`、`mask-preview.png`、`workflow.json`、
`request.json`、`queued.json`、`history.json`、`generated.png`、`result.png`、
`result-native.png`、`comparison.png` 与 `report.json`。
每次运行先把报告重置为 prepared，只有成功取图并通过像素检查才写 passed。
`report.json` 的 `visual_review: pending` 表示仍需肉眼检查风格与接缝。

生成图只按蒙版合入原始 RGBA 图，透明区也保留原值；模型的全图解码变化不会覆盖蒙版外的像素。
冒烟验证只证明模型与命令通路可用，任务 7.1–7.3 仍需正式分层、全部缺口补齐及重复执行验收。

## 已知的坑

- **2048 参考图的墨迹会把内容包围盒撑大**。参考立绘带着大量接近黑色的墨迹装饰，在黑底上几乎看不见，
  抠底之后变成可见黑块，包围盒被撑到 1848×1757，而角色本体只有七百多像素宽。
  所以拆件的裁剪范围要按**角色本体**量，不能直接用脚本报的内容包围盒。
- **重叠余量会让边缘像素被叠两次**，所以拼装自检要分开统计"全不透明"和"含边缘过渡"。
- **部件是按矩形裁的**，不是按轮廓。重叠余量给足才不会露缝；余量最终还是不够的地方，
  就落到缺口报告里交给 ComfyUI。
